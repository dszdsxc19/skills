# 项目本地笔记

## 默认约定

- 笔记保存在 Git 仓库根目录 `.local-notes/`，采用易识别的主题文件名，优先 Markdown；按内容需要保留 Mermaid 图、源码链接和验收条件。
- 本地排除规则为 `/.local-notes/`，写入 `git rev-parse --git-path info/exclude` 返回的实际文件。不要假设 `.git` 一定是目录，兼容 linked worktree。
- 不修改共享 `.gitignore`、不提交笔记、不为发现笔记修改项目 AGENTS.md。忽略规则与笔记不会随普通 commit/push 或 clone 同步；同一 Git 仓库的关联 worktree 可能共享排除配置，但笔记文件仍在各自工作目录。
- Git ignore 不阻止强制添加，也不保护已跟踪文件，不用于保管秘密。

## 创建或设置

1. 确认仓库根、工作区状态和相关目录指令。检查 `.local-notes/` 是否已有同主题笔记，优先增补；不得覆盖现有同名文件。
2. 用 `git ls-files -- .local-notes` 检查已跟踪文件。若存在，说明 ignore 不会让它们自动退出版本管理；不擅自执行 `git rm --cached`，先明确用户希望如何处理。
3. 读取实际 exclude 文件，保留原内容，仅在缺少该行时追加 `/.local-notes/`，保证重复运行不重复添加。
4. 创建目录和用户要求的文档。将“现有实现”“拟议方案”“待决策”“验收条件”区分清楚，记录必要的代码核对时间或基线，避免把草案当成上线事实。
5. 用户要求迁移已有文件时，先完成复制并核对，再删除原文件；只要求留档时保留原件。同名冲突不覆盖。
6. 用 `git check-ignore -v -- .local-notes/<文件>` 验证规则命中；用 `git ls-files -- .local-notes` 和 `git status --short` 验证未被跟踪且未引入无关改动。说明 ignore 不会改变已存在的用户修改。

## 跨会话发现与续作

- 用户说“继续上次方案”“之前本地保存的文档”且目标属于当前项目时，先列出 `.local-notes/` 再匹配主题，不依赖旧会话或临时目录路径。
- 此目录已被 Git 忽略，普通 `rg --files` 可能跳过它。使用范围受限的 `rg --files --hidden --no-ignore .local-notes`；不要扩大为全仓库无忽略扫描。
- 有多个主题时维护 `.local-notes/README.md` 简短索引，包含相对链接、主题和状态；单份笔记无需额外建索引。
- 只读取当前问题相关笔记，并用当前源码核对旧结论。笔记中的待办不构成实施、部署或外部写入授权。

## 交付

返回文档绝对路径链接、忽略验证结果，以及可直接复用的续作口令：

> 读取 `.local-notes/<主题>.md`，继续讨论／实现……

首次设置时说明仅本地保存；换电脑、重新 clone 或删除工作目录前需要另行迁移或备份。不要承诺每个新会话都会自动加载，应通过个人协作手册的触发规则或显式 `$local-project-notes` 调用发现。
