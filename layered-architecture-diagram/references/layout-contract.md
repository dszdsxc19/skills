# 布局与语义契约

## 1. 图形骨架

推荐画布比例为 4:3、16:10 或接近横向 A4。布局由三个区域组成：

```text
┌──────────┬────────────────────────────────────┬──────────┐
│ 左侧层级栏 │               实体区                │ 横切能力柱 │
├──────────┼────────────────────────────────────┼──────────┤
│ 接入层     │ [用户] → [客户端] → [API]           │ 身份安全   │
├──────────┼────────────────────────────────────┤ 生命周期   │
│ 应用层     │ [身份] → [Runtime] → [Memory]       │ 可观测性   │
├──────────┼────────────────────────────────────┤ 发布配置   │
│ 编排层     │ [Resolver] → [Workspace] → [Registry]│          │
├──────────┼────────────────────────────────────┤          │
│ 平台层     │ [OpenAPI] → [Application] → [Image] │          │
├──────────┼────────────────────────────────────┤          │
│ 运行层     │ [Instance] [File] [Shell] [Mount]   │          │
├──────────┼────────────────────────────────────┤          │
│ 数据层     │ [NAS] [Database] [External API]     │          │
└──────────┴────────────────────────────────────┴──────────┘
```

层数由真实实体决定，通常为 5–7 层。不要为了达到固定层数拆分只有一个实体的伪层。

## 2. 实体归层

常见职责顺序：

1. 客户端与接入：用户、Web、App、API 入口、Session、路由。
2. 应用控制：Request Context、Agent、Workflow、Memory、业务控制器。
3. 编排与控制面：Resolver、Registry、Scheduler、Token Provider、分布式锁。
4. 云平台管控：平台 OpenAPI、Application、Revision、Endpoint、预热池。
5. 运行时：容器、Sandbox、Pod、VM、文件与命令执行接口、挂载点。
6. 存储与外部能力：数据库、NAS、对象存储、外部 HTTP 服务。

以下实体不能混淆：

- 逻辑会话与运行实例。
- 控制面 Registry 与实际 Sandbox。
- 镜像 Revision 与由镜像创建的实例。
- 挂载点与后端持久化目录。
- 用户身份键、会话键和实例键。

## 3. 主链路

- 只选择一条能解释系统工作的主调用链。
- 主链路必须从入口到运行或存储终点连续贯穿。
- 同层优先水平连接，跨层优先垂直连接。
- 跨层转折放在层间留白区，使用两段或三段正交折线。
- 主链路箭头为 3–4px，支撑依赖为 1.5–2px。
- 支撑依赖不超过主链路数量的两倍；再多时应合并成总线或省略。

## 4. 横切能力

只有真正作用于三个以上层级的能力才进入右侧纵向能力柱。常见类型：

- 身份与安全。
- 生命周期与资源回收。
- Trace、日志、指标与告警。
- 配置、镜像与发布管理。

横切能力柱不再向每个节点分别画虚线。使用贯穿区域表达作用范围，在柱内列 3–5 个关键词。

## 5. 边界和不变量

系统边界、云平台边界、运行环境边界应通过层或浅色区域表达，不能只靠文字说明。

以下信息适合写在副标题或底部图例中：

- `threadId → instanceId` 等实例映射。
- `resourceId → persistent storage` 等存储归属。
- 单会话独占、用户级复用、只挂载叶子目录等隔离规则。

不要把完整接口参数、异常分支、重试策略和大段说明塞进总览图；这些内容应进入时序图或正文。
