# 最终载体、制图工具与格式路由

本文件只决定“用什么画、以什么格式交付”。架构语义、分层、实体归属、关系和视觉规范仍以主 Skill 为准。

## 路由原则

1. 用户明确指定工具或格式时直接采用；若与目标平台不兼容，交付指定源文件并附可展示预览。
2. 未指定时优先选择目标平台的原生可编辑格式。
3. 简洁且需要文本版本管理的图优先 Mermaid；复杂、强调空间控制和企业级视觉的分层图优先原生图元、SVG、Draw.io 或 Excalidraw。
4. 静态交付同时提供源格式与预览格式；动态交付保留可复现源码。
5. 实体和关系必须精确，不使用图片生成模型绘制含关键文字、连线和边界的技术架构图。

## 飞书画板路径

- 先读取 `lark-doc` 和 `lark-whiteboard` 的完整指令，再按画板工作流执行。
- 复杂分层架构图优先使用可控的 SVG 或画板 DSL 转换为原生画板节点；不要把截图当作最终画板。
- 写入后必须查询或导出画板预览验证。若预览空白、只剩背景或节点被遮挡，检查图元创建顺序与 `z_index`，修复后重新回读。
- 文档中已有目标画板时更新该画板；没有目标画板且用户授权编辑文档时，再创建并插入新画板。

## 格式专用约束

### Mermaid

- 仅用于层级不多、布局无需像素级控制、节点和边能完整表达语义的图。
- 保持源码可读，避免依赖不稳定的自动布局完成复杂横切能力柱。

### SVG

- 只保留一个根 `<svg>`，包含 `viewBox`。
- 文字使用 `<text>`；中文字体包含 `Noto Sans SC` 或 `PingFang SC`。
- 同时渲染 PNG 预览，验证溢出、遮挡和层叠顺序。

### 原生图元格式

- 优先使用目标平台的形状、文本、连接线、分组和层级能力。
- 连接线必须绑定节点或稳定锚点；移动实体后关系仍应保持正确。
- 避免把整张图扁平化为单张背景图。

### 交互 HTML

- 静态状态必须已经可读，交互只用于补充筛选、缩放、聚焦和详情。
- 保留可复现的源码与无需交互也能审阅的静态截图。

## 交付检查

- 目标平台可以直接打开，不依赖未提供的本地资源。
- 原生源、预览和文档内展示内容一致。
- 预览来自最终载体或最终导出结果，而不是中间草稿。
- 用户未要求教程说明时，只报告图名、载体、源格式和验证结果。
