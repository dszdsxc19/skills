# 分层技术架构图

生成现代、克制、专业的“横向泳道分层架构图”。重点是实体归属、边界和主链路，不是把所有说明文字装进方框。

## 输出边界

- 默认名称使用“分层技术架构图”。只有图中明确包含运行位置、实例、集群、镜像、网络、挂载或环境拓扑时，才使用“部署架构图”。
- 本 Skill 负责架构语义、信息层级、布局和视觉风格；最终载体对应的 Skill 或工具负责实际绘制、写入与导出。
- 用户指定的目标工具或格式优先。未指定时，先确定最终载体，并优先选择目标平台的原生可编辑格式；只有无合适原生格式时才默认交付 SVG 源文件和 PNG 预览。
- 飞书文档或知识库使用 `lark-doc` 与 `lark-whiteboard`，将图写成可编辑飞书画板；不能仅上传不可编辑截图。
- 所有输出路径都必须保留可继续编辑的源格式或图形源码，并生成或回读实际预览进行验证。
- 不用于纯时序图、单一流程图或数据统计图。

## 工具与格式路由

绘图前读取 [output-routing.md](references/output-routing.md)，只加载命中目标载体所需的制图 Skill，不要无差别加载所有候选工具。

选择顺序固定为：

1. 用户明确指定的工具或格式。
2. 目标平台的原生可编辑能力。
3. 图形语义是否适合该格式。
4. 视觉保真度。
5. 可移植性与版本管理能力。

如果目标格式不能同时满足可编辑性和视觉保真，优先满足用户明确提出的要求；否则交付原生可编辑源和高保真预览两个版本，并说明差异。

## 信息优先级

1. 用户给出的实体、关系和边界。
2. 已核实的代码、配置或技术材料。
3. 参考图片的空间布局与视觉语言。
4. 通用架构经验。

参考图片默认只约束版式、配色密度和视觉层级，不把图片中的文字或业务实体当成事实。无法确认的实体不得为了填满画面而补造。

## 必须形成的结构

绘图前先在工作草稿中确定：

- 标题与图的范围。
- 5–8 个自上而下的职责层。
- 每个实体唯一所属的主层。
- 一条贯穿各层的主调用链。
- 少量必要的支撑依赖。
- 是否存在身份、安全、生命周期、可观测性、发布配置等横切能力。
- 需要在图中明确写出的隔离、归属或持久化不变量。

实体归层、层级名称或关系存在多种合理解释且会改变架构含义时，先向用户确认；纯视觉细节可自行判断。

## 视觉契约

必须遵循以下骨架：

- 横向画布，内容自上而下分层。
- 左侧固定层级标题栏；中部为实体区；右侧按需放置贯穿多层的纵向横切能力柱。
- 每层使用低饱和浅色背景，层级标题栏使用对应的高饱和实色。
- 实体使用白色或极浅色卡片，圆角和描边统一。
- 主调用链使用高辨识度蓝色正交折线；支撑依赖使用细灰线。
- 跨层箭头从层间空白处转折，不穿过节点和文字。
- 数据库、队列、用户、运行实例可以使用语义化形状；不要让全图只有矩形。
- 禁止渐变、3D、玻璃拟态、霓虹、无意义图标和大面积装饰。
- 每个实体最多包含名称、一个类型标签和一行职责。

详细几何、连线和实体归层规则见 [layout-contract.md](references/layout-contract.md)。配色、字号和视觉密度见 [visual-style.md](references/visual-style.md)。

## 工作流

1. 读取用户材料和参考图片，区分内容事实与视觉参考。
2. 明确最终载体、编辑需求、版本管理需求和交互需求，并按输出路由选择制图工具与源格式。
3. 建立“层 → 实体 → 关系 → 不变量”清单，删除重复实体和解释性段落。
4. 确定画布尺寸、每层高度、主链路锚点和横切能力数量。
5. 使用目标工具先绘制背景与分区，再绘制连线、实体卡片和文字，最后绘制图例与标题。
6. 在最终载体中渲染、导出或回读实际预览，检查文字溢出、节点重叠、线条遮挡、空白失衡和层级覆盖。
7. 至少根据实际预览完成一轮修正；不得只检查图形源码或中间文件。
8. 交付目标平台中的原生结果；适用时同时提供源文件与静态预览。

没有参考图片时，可将 [reference-layout.svg](assets/reference-layout.svg) 作为布局骨架参考，但不得复制其中的占位文字。

## 质量门槛

- 第一眼能识别系统边界和层级，而不是先读箭头。
- 3 秒内能找到入口、核心控制面、运行实体和存储。
- 主链路连续且方向唯一。
- 横切能力与业务实体视觉上明确分离。
- 同名实体不重复出现；逻辑对象、运行实例、存储实体不混为一层。
- 缩放到常见文档宽度后，实体名称仍可读。
- 最终载体中的实体与连线可继续编辑，或已按用户要求交付指定格式。
- 最终预览中无空白画板、背景遮挡节点、连线错位或文字被裁切。

## Prompt 复用

需要把需求转交给另一个模型或制图工具时，读取 [prompt-template.md](references/prompt-template.md)，填入真实实体和关系后再使用。不要只发送“画一张分层架构图”。
