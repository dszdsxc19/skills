# 结构与证据口径

## 时间表

按实际事件排序，推荐列：时间（含时区）｜阶段｜事件、人员与证据。保留与因果或恢复判断有关的事件，不写调查过程流水账。

相关事件包括：代码引入、合入、发布完成、使故障路径生效的组合变更、首次已知失败、告警 / 用户报告、缓解措施、修复合入、修复发布完成、首次成功验收、后续优化完成。无法取得精确时间就保留已有精度，不用工单更新时间代替开始时间。

人员按作者、MR 创建者、自动合并者、发布发起人和执行人分别归属；记录行为事实，不推断个人动机或责任。

## 时长表

| 口径 | 起止 | 解释 |
| --- | --- | --- |
| 潜在风险期 | 缺陷版本发布 → 修复生效边界 | 可能包含尚未进入该路径的阶段 |
| 业务路径暴露期 | 必要组合全部上线 → 修复生效边界 | 不表示所有请求持续失败 |
| 已知故障至处置 / 验收 | 首条已知失败 → 指定处置或成功验收 | 事件间隔，不默认称故障持续时间 |
| 实际连续故障时长 | 有证据的失效起点 → 有证据的恢复点 | 无完整观测则待确认；间歇故障需分段 |

计算使用同一时区和真实时间戳；注明分钟等展示精度。无关口径省略。发布边界是否能视为风险终止取决于实际流量与版本切换，不能仅凭工单结束推定全量恢复。

## 影响与证据

对重要结论保存“结论｜来源｜环境 / 版本｜观测时间｜验证方式｜局限”。可作为工作材料或附录，无需正文再复制一整张账本。

- 现场：日志、trace、错误码、关键输入；请求体由代码重建时明确注明。
- 复现：相同点与差异、默认执行路径、数据规模、结果及失败阶段。
- 推断：给出依据与仍需验证的环节，不伪装成现场事实。
- 影响：已确认与潜在风险分开，明确采样范围和分母；没有统计时写未知。

## 对比与验收

对比表按实际任务选列：行为 / 结果集合、执行机制、索引或资源、耗时、错误率、资源开销。控制输入、环境、缓存与计时口径；SQL 耗时、RPC 延迟和 CLI 总耗时不能混算。少量样本报告次数、范围或中位数，不包装为稳定 p95 / p99。

正确性不变量可包括 ID 集合与顺序、去重、分页不漏不重、软删除、权限、返回结构。优化副作用可包括写入维护、存储、构建压力、计划不稳定或适用范围限制；只讨论与本次变更有关的内容。

真实验收以业务响应与内容为准，工具外层 success 不足以证明业务成功。参数封装错误等无效调试样本单独记录并排除；真实失败不能为了好看的结果被排除。

预防措施写清对应漏检机制、测试数据 / 边界、环境、观察指标、通过条件和执行阶段。只有已知或用户指定时填写负责人、期限和门禁预算，不发明承诺。性能阈值需来自实际超时预算与余量；不要将特定执行计划关键字一律当作失败。
