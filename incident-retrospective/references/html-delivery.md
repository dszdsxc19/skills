# HTML 呈现与交付

借鉴用户确认的 SearchAssets 复盘形式，复用信息层次而非事故内容。不要复制旧车系、人员、日期、工单、性能数字或云文件 token 为新报告默认值。

## 页面组织

- 开篇：一句话根因、标题、发生日期、带时区的核验截止时间；修复 / 发布 / 验收 / 待办各自标状态。文案更新时间不冒充生产状态核验时间。
- 正文：现场与调用链、时间线与时长、影响、根因与前后执行图、同口径实测、优化方案、漏检与预防、验收。按事件裁剪或合并。
- 附录：可折叠的日志、请求、SQL、执行计划、提交与工单链接、测试记录；正文无需反复粘贴。
- 长文可用章节锚点与打印 / PDF 按钮；打印时展开附录并隐藏导航按钮，避免截断证据。

视觉保持白底、深色正文、克制蓝色强调、清晰层级和留白；成功 / 失败 / 待确认同时有文字标签，不只靠颜色。图中文字在普通阅读宽度下可读，移动端改为纵排或表格横向滚动，不压缩字号塞进一屏。

每张图回答一个问题：调用链定位错误传播，前后并排图展示机制变化，表格比较指标，时间表展示事件。保留真实服务 / 数据库边界，箭头含义统一。根因图显式标注“现场确认”“同条件复现”或“推断”。

## 机制说明的措辞

不把数量上限写成必须达到的目标，不把结果数量写成扫描数量。例如分页应写：

> 末页匹配结果不足 LIMIT，需检查完剩余候选范围才能确认结束。

若使用具体数字，先有对应证据。EXISTS 的关系查找提前结束不等于整个分页停止；有排序时也不能保证凑够结果即可结束所有扫描。此例用于防止误导，不将 SQL 专项章节强加给其他事故。

## 文件与云端交付

- 单文件 HTML 使用内联 CSS、必要 JS / SVG，不依赖本机相对资源；优先复用已有样式和结构，避免文案更新导致全面重排。
- 用户指定原始 HTML 文件时，直接更新原文件，不转成 Docx。指定内嵌 HTML5 块或原生文档时遵从其目标。
- 上传飞书时复用已安装 `feishu-html-delivery` 与 `lark-drive` 技能；只有文档交付被授权才写云端。不要把报告创建自动扩展为消息通知或权限变更。
- 修改现有云文件前回读最新源内容，保留并发改动；按目标 file token 原位更新，保留链接和共享范围。
- 本地核对 HTML 内容、章节链接和旧措辞清理；云端上传后回读比对，并在真实预览普通视口检查新增图表、文字和交互。无法预览就说明未验证，不声称视觉验收通过。
