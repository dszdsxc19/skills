# 审看与验收

## 技术事实

`verify.py` 检查尺寸、帧率、帧数、时长、全片解码、镜头清单和音轨长度。缺少必要输入时给出具体原因，保留已完成成果。

黑帧区间、声道差异、响度与冻结提示记录为观察。是否错误取决于影片意图与用户规格；不要为“有运动”“够响”“够宽”制造无意义画面和声音。

## 实际画面

检查关键动作开始、中间、落定，以及镜头衔接附近的连续帧。最终 MP4 再抽看一次，避免把中间图当成最终编码结果。

- 主角及动作是否能被看见，桌面、柜台、前景是否遮挡。
- 行走、抓取、传递、合并、分流是否建立正确的空间关系。
- 数字是否对应当前画面和同一计数口径。
- 字幕是否能在实际输出尺寸下读完，有无溢出、落单字或遮挡。
- 主动作结束后是否存在没有目的的空等。
- 图文与场景的切换是否服务叙述，机位和对象是否意外重置。
- 声音是否对应动作，旁白清楚，结尾有完整收束。

技术检查通过只证明文件和时间轴符合检查项。叙事、审美与听感写实际观察，未验证部分说明范围。

## 修正与交付

定位到具体镜头和事件，先修证据指向的问题。局部改三维时输出新版镜头；只改图文或声音时保留三维帧。保留上一版成片供对照。

交付可播放视频和编辑入口。可用分镜图或同一帧的“Blender 底图 / Python 图文 / 合成结果”帮助解释分工，但这类图不能代替运动审看。
